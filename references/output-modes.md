# 三种输出模式

同一个设计系统可以输出三种版本。开工前必须先和用户确认用哪一种，默认推荐“动效解说版”。

## 1. 动效解说版（全动画）

**是什么：** 画面全部是动效合成，不保留原始视频画面，只保留/复用旁白。

**适合：** 原始视频主要是口播、屏幕录制、画面本身没有观赏价值；需要统一的编辑风视觉、方便后续改文案或换配音。

**实现：**

- 工程里只有 `<audio>`，没有 `<video>`。
- 根合成里全是场景容器、卡片、图表、字幕。
- 背景、转场、入场动效完全由 HyperFrames 控制。

**用户可以说：**

```text
做成动效解说版，先出预览图
```

## 2. 视频背景 + 新闻叠加版（叠加版）

**是什么：** 原始视频继续作为背景播放，在上面叠加新闻风 UI：眉题、标题卡、关键数字卡、可选字幕胶囊。

**适合：** 原始视频本身有值得保留的画面（实拍、产品演示、采访、录屏），只需要补充新闻式标注和节奏。

**实现：**

- `<video>` 必须 `muted playsinline`，横铺全屏或居中作为背景。
- 旁白用独立的 `<audio>` 元素。
- 叠加层 `z-index` 高于视频，放在安全区：左上眉题、左上/中间标题、底部字幕，避免盖住视频关键内容。
- 叠加层不要用整屏不透明背景；卡片和文字可以用半透明/白底。
- 场景“转场”主要作用在叠加层，视频可以连续播放。

**用户可以说：**

```text
保留原视频画面，做成视频背景 + 新闻叠加版
```

## 3. 混合版

**是什么：** 原视频和动画解说穿插：视频表现“现场/演示”，动画场景负责“定义/数据/对比/总结”。

**适合：** 视频里一部分画面值得保留，一部分抽象概念用动画更好讲；也适合做节目感更强的成品。

**实现：**

- 同一根合成里同时有视频片段和动画场景。
- 视频片段用 `data-start` / `data-duration` 精确排进时间线，动画场景按旁白节拍插入。
- 视频片段之间、动画场景之间都用统一转场衔接。
- 音频仍然独立；视频只做画面，不出声。

**用户可以说：**

```text
做成混合版：录屏和实拍保留原视频，定义和数据部分用动画
```

## 选择建议

| 情况 | 推荐模式 |
| --- | --- |
| 口播/屏幕录制、画面无强信息 | 动效解说版 |
| 实拍/演示/产品画面有价值 | 视频背景 + 新闻叠加版 |
| 一部分画面有价值、一部分需要解释 | 混合版 |
| 不确定 | 先问用户，默认动效解说版 |

## HyperFrames 注意事项

- 视频永远 `muted playsinline`，声音永远来自独立 `<audio>`。
- 不要把 `<video>` 直接嵌在带 `data-start` 的容器里；需要移动/缩放视频时包一层 wrapper 再动 wrapper。
- 叠加版和混合版里，动画元素不能挡住视频的关键信息区。
- 三种模式都必须遵守主流程：先预览图，用户确认后再渲染。
